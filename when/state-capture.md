# Where does a fact go?

Opened because a fact's home is not obvious, a new name resembles an existing one, or new information contradicts what is recorded.

- When a fact needs a home and no existing file answers its question: raise the gap with the user, never invent a destination.
- When a project has a question with no file bound to it and content arrives for it: create the file, name it for the question it answers, and declare it in the project's CLAUDE.md in the same turn.
- When a project file would answer a question a global file already answers: stop — one question, one home.
- When a new name resembles an existing canonical one: ask before merging entities.
- When facts come from documents rather than the user directly: build a working list and confirm item by item — documents are intermediaries, the user is the source of truth.
- When new information contradicts recorded content: present both sides with dates and sources; never resolve it unilaterally.
- When durable state changes: update its home immediately, not at session end.
