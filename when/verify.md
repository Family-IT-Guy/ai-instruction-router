# Verify

Opened because a check is about to happen. The speed-bias stop, the hedge rule, the denominator rule, and the copy-from-file rule already fired from ROUTER.md. This file is the rest of the methods.

A check happens at the layer where failure shows. Incomplete-and-accurate beats complete-and-wrong.

| When | Do | Why |
|---|---|---|
| Document scan | Grep the pattern across the full file. Do not rely on having read it. | Reading misses the line nobody is looking for. |
| Skill execution | Run the full process after the draft. Loading it "in mind" is not executing. | |
| UI inspection | Official docs plus the receiving end, before "X doesn't exist." | |
| System audit | Draw the end-to-end data flow before listing problems. | |
| Problem inventory | Validate each claim before presenting it as an action. | |
| Test-harness failure | Reproduce in isolation before calling it real. | |
| Fixture for a database, API, or file | Build it from one real call's shape. Never from hand-written ideal values. | A planner sorted Postgres numerics that arrive as strings, so `"3.5"` outranked `"19.4"`, while tests against float literals stayed green. |
| Spec or plan touching existing systems | Grep implementations. Read the auth chain to the end. Query production for field names. List every entry point. If the system already does it, say so. | |
| Plan or spec for anything being built | Give each milestone evidence that distinguishes success from failure and name who accepts it. A lookup has a real command and a machine-comparable reading; a judgment names the original requirements, artifacts and decisive observations to assess. The final milestone establishes the integrated outcome. Keep the checks where a later session will find them. | A command that checks superficial wording cannot establish a judgment. |
| Constraint (page limit, word count, scope) carried from a previous session | Revalidate with the user. | |
| Marketing term or vendor claim in an analysis | Demand a measurement. | |
| Data comparison presented as evidence | Check alternative explanations before claiming causation. | |
| Verdict on work | Follows the evidence in both directions. Sound work is confirmed as plainly as an error is named. A concern about a nearby decision that was not asked is a new question, not part of this verdict. | |
